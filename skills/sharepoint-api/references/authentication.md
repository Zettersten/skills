# SharePoint Authentication Guide

Complete guide for SharePoint/OneDrive profile management with the integrated provisioning wizard.

## Overview

This skill uses **agent-browser** profiles to maintain authenticated SharePoint sessions. Profiles are stored within the skill directory and managed automatically.

**Profile location**: `<skill-dir>/profile/`  
**Configuration**: `<skill-dir>/.config`

## First-Time Setup

### Automatic Provisioning

The skill automatically provisions a profile on first use:

```bash
# Navigate to skill directory
cd /path/to/skills/sharepoint-api

# Create session (launches wizard if needed)
bash scripts/session-manager.sh create
```

You'll see:

```
═══════════════════════════════════════════════════════
  Profile Not Provisioned
═══════════════════════════════════════════════════════

This skill requires a SharePoint browser profile to be provisioned.

Would you like to provision a profile now? [Y/n]
```

Press `Y` to start the wizard.

### Manual Provisioning

Run the wizard explicitly:

```bash
bash scripts/provision-profile.sh
```

## Provision Wizard Walkthrough

### Step 1: Select Tenant Type

```
▶ Step 1/5: Select Tenant Type

Select your SharePoint tenant type:

  1) Commercial (.sharepoint.com)
  2) GCC High (.sharepoint.us)
  3) Custom (enter manually)

Choice [1-3]:
```

Choose your environment:
- **1** - Standard Microsoft 365 / Commercial
- **2** - US Government GCC High / DoD
- **3** - Custom (manual URL entry)

### Step 2: Configure Tenant URL

**For Commercial/GCC High**:

```
▶ Step 2/5: Configure Tenant URL

Enter your tenant name (subdomain only):
Example: For https://contoso.sharepoint.com, enter: contoso

Tenant name:
```

Enter just the subdomain (e.g., `contoso`, `agency`).

**For Custom**:

```
Enter your SharePoint tenant URL:
Example: https://contoso.sharepoint.com

Tenant URL:
```

Enter the full URL.

### Step 3: Configure User Path

**For Commercial/GCC High**:

```
▶ Step 3/5: Configure User Path

Enter your username (before the @ in your email):
Example: For john@contoso.com, enter: john

Username:
```

Enter your username only (before `@`).

The wizard automatically constructs the user path based on tenant type.

**For Custom**:

```
Enter your personal site path:
Example: /personal/john_contoso_com

User path:
```

Enter the full user path.

### Step 4: Create Profile

```
▶ Step 4/5: Create Profile Directory

Profile directory created: /path/to/skill/profile
Configuration saved: /path/to/skill/.config
```

Profile directory and configuration file created automatically.

### Step 5: Authenticate

```
▶ Step 5/5: Authenticate Browser

Opening browser for authentication...

Please complete the following steps in the browser:
  1. Enter your Microsoft 365 username
  2. Enter your password
  3. Complete MFA if required
  4. Verify you can access your OneDrive
  5. Close the browser window or press Ctrl+C here when done

Press Enter to open browser...
```

Press Enter. A browser window opens with your SharePoint tenant.

**Complete authentication**:
1. Sign in with your Microsoft 365 credentials
2. Complete multi-factor authentication (if enabled)
3. Verify you see your OneDrive homepage
4. Close the browser window or press Ctrl+C

## Configuration File Format

The wizard creates `.config` with:

```bash
# SharePoint API Skill Configuration
# Auto-generated by provision-profile.sh

# Tenant configuration
export SP_TENANT_URL="https://tenant.sharepoint.com"
export SP_USER_PATH="/personal/user_tenant_com"
export SP_TENANT_TYPE="commercial"

# Profile location (relative to skill directory)
export SP_PROFILE_PATH="/path/to/skill/profile"

# Session prefix for agent-browser
export SP_SESSION_PREFIX="sharepoint"

# RenderListDataAsStream options
export SP_RENDER_OPTIONS="5691143"
```

All scripts automatically load this file.

## Re-provisioning

### Change Tenant

To switch tenants or re-authenticate:

```bash
bash scripts/provision-profile.sh
```

The wizard detects the existing profile:

```
⚠ Existing profile detected

Profile location: /path/to/skill/profile
Configuration: /path/to/skill/.config

Current configuration:
  Tenant URL: https://tenant.sharepoint.com
  User Path: /personal/user_tenant_com

Do you want to re-provision (this will overwrite)? [y/N]
```

Press `y` to overwrite and re-run the wizard.

### Manual Configuration Edit

Advanced users can edit `.config` directly:

```bash
# Edit configuration
vi /path/to/skill/.config

# Verify
bash scripts/session-manager.sh status
```

**Note**: Editing `.config` doesn't re-authenticate the browser profile. Re-run the wizard to update authentication.

## Session Lifecycle

### Create Session

```bash
bash scripts/session-manager.sh create
```

Checks for profile, loads configuration, creates browser session.

### Check Status

```bash
bash scripts/session-manager.sh status
```

Shows:
- Session ID
- Tenant URL
- Profile path
- Browser running status
- Authentication validity

### Destroy Session

```bash
bash scripts/session-manager.sh destroy
```

Closes browser, keeps profile and configuration intact.

### Force Cleanup

```bash
bash scripts/session-manager.sh cleanup
```

Kills all Chrome processes, removes locks. Use when browser is stuck.

## Tenant-Specific Notes

### Commercial (.sharepoint.com)

- **URL**: `https://TENANT.sharepoint.com`
- **User path**: `/personal/USER_TENANT_com`
- **Authentication**: Standard Microsoft 365

### GCC High (.sharepoint.us)

- **URL**: `https://TENANT.sharepoint.us`
- **User path**: `/personal/USER_TENANT_onmicrosoft_us`
- **Authentication**: GCC High credentials (separate from Commercial)

**Important**: GCC High requires separate authentication. Cannot reuse Commercial credentials.

## Troubleshooting

### Profile Lock Error

**Symptom**: `Failed to create SingletonLock`

**Solution**:
```bash
bash scripts/session-manager.sh cleanup
```

Session-manager automatically handles lock cleanup on `create`.

### Authentication Expired

**Symptom**: 401 Unauthorized errors

**Solution**: Re-run provision wizard
```bash
bash scripts/provision-profile.sh
```

Re-authenticate in Step 5.

### Wrong Tenant

**Symptom**: Redirects, 404 errors

**Solution**: Re-provision with correct tenant type
```bash
bash scripts/provision-profile.sh
# Select correct tenant type (Commercial vs GCC High)
```

### Profile Corruption

**Symptom**: Persistent authentication failures

**Solution**: Delete and re-provision
```bash
# Delete profile
rm -rf /path/to/skill/profile
rm -f /path/to/skill/.config

# Re-provision
bash scripts/provision-profile.sh
```

## Multiple Tenants

To use the skill with multiple tenants, copy the entire skill directory:

```bash
# Copy skill for each tenant
cp -r sharepoint-api sharepoint-api-commercial
cp -r sharepoint-api sharepoint-api-gcc-high

# Provision each separately
cd sharepoint-api-commercial
bash scripts/provision-profile.sh
# Select Commercial, complete wizard

cd ../sharepoint-api-gcc-high
bash scripts/provision-profile.sh
# Select GCC High, complete wizard
```

Each copy maintains independent profiles and configuration.

## Security Considerations

### Profile Contents

Profiles contain:
- Browser cookies (authentication tokens)
- Session data
- Local storage
- Cache

**Protect profile directories**: Set restrictive permissions
```bash
chmod 700 profile/
```

### Git Ignore

The skill includes `.gitignore` to exclude:
- `profile/` - Authenticated browser data
- `.config` - Tenant-specific configuration

**Never commit profiles to version control.**

### Credential Rotation

Re-provision when:
- Passwords change
- MFA settings update
- Tenant policies change
- Authentication expires (typically 90 days)

## Automation

## Advanced: Manual Profile Creation

For users who want full control:

```bash
# Create profile directory
mkdir -p /path/to/skill/profile

# Create configuration
cat > /path/to/skill/.config <<EOF
export SP_TENANT_URL="https://tenant.sharepoint.com"
export SP_USER_PATH="/personal/user_tenant_com"
export SP_PROFILE_PATH="/path/to/skill/profile"
export SP_SESSION_PREFIX="sharepoint"
export SP_RENDER_OPTIONS="5691143"
EOF

# Authenticate
agent-browser --profile /path/to/skill/profile \
  open https://tenant.sharepoint.com
# Complete authentication, close browser

# Test
bash scripts/session-manager.sh status
```

Most users should use the provision wizard instead.
